## 4. What must not be lost

- Prerendered static HTML per route (SEO, speed, zero server cost).
- `pending` / awaiting-panel honesty pattern.
- Theme (light/dark via `ThemeService`, `[data-theme]`), custom cursor, reveal/count-up with reduced-motion handling.
- QR generator (UTF-8 encoder fix, level-H EC, integer module size — see README).
- Trailing-slash URL serializer (all routes end in `/`).
- Floating pill navbar, search bar (`search.data.ts`).
- Control Room's working features: registration + permanent participant IDs,
  NEC attribution, offline QR check-in, sessions/attendance, certificates,
  feedback, blueprints→requests, creators, audit log, super-admin guard.

## 5. Technical debt / risks found

1. Two frontends in two frameworks for one brand (Angular public, React platform).
2. Content edits require a developer + rebuild + deploy (the core pain point).
3. Events' upcoming/past only recomputed on rebuild.
4. `/control/` is public; anyone with the URL can use it (harmless today, not a pattern to extend).
5. `meet-the-team.mp4` committed to Git — media in Git.
6. Sitemap route list duplicated and stale.
7. *(Fixed 2026-09-25)* `_headers` existed in two places (`public/_headers` and a postbuild fallback) with **different** `X-Frame-Options` values (SAMEORIGIN vs DENY).
8. Production branch is `ECell`, not `main` — a documented footgun.
9. Control Room role model is a **single enum ladder** (`public < member < core < faculty < admin < super_admin`), with `canX(role)` checks — the brief explicitly forbids this for the target (role ≠ vertical, permission-based).
10. `site_content` is a flat key/value text table — no drafts, versions or scheduling.
11. Control Room repo is owned by a personal GitHub account — **bus-factor / succession risk**; should move to an org.
12. No tests in `web/` beyond the scaffold; Control Room has verify scripts, not a test suite.
13. `ecell/.env.local` presence UNVERIFIED; `.env.example` exists (good). No secrets found committed in `web/`.
