# PSGIM E-Cell — website

The website of the Entrepreneurship Cell, PSG Institute of Management, Coimbatore.

Plain static HTML, CSS and JavaScript, generated by a small build script with
**no dependencies**. `npm install` does nothing; there is nothing to install.

```bash
node build.mjs           # build into dist/
node build.mjs --serve   # build, then preview on http://localhost:4321
```

Deploy `dist/` to Cloudflare Pages. Build command `node build.mjs`, output
directory `dist`.

---

## Editing content — you do not need to touch the design

Everything a visitor reads lives in **`src/data/`**. Change a file there and
rebuild; no template or stylesheet needs to change.

| File | What it holds |
| --- | --- |
| `site.js` | Name, address, email, social accounts, navigation, the notice bar |
| `about.js` | Homepage intro, the story, vision & mission, timeline, mentors, testimonials |
| `initiatives.js` | The six programmes, and the four stages of the arc |
| `events.js` | The calendar |
| `team.js` | Faculty, patron, working roles, the NEC campaign team |
| `stats.js` | The four homepage figures, and the NEC drive targets |
| `gallery.js` | Gallery tiles and albums |
| `nec.js` | Everything on the NEC page |

### The "to be confirmed" convention

Anything the team has not yet verified carries `pending: true`. The site then
renders it with a visible *to be confirmed* marker instead of presenting it as
established fact:

```js
email: { value: "ecell@psgim.ac.in", pending: true },
```

Once the office confirms it, drop the flag:

```js
email: { value: "ecell@psgim.ac.in" },
```

This is deliberate. An institutional site that states an unverified figure
plainly is worse than one that says it is still checking.

### Things that are empty on purpose

`mentors` and `testimonials` in `about.js` are empty arrays. The previous
version of the site shipped invented people ("Speaker one", "Investor five")
and unattributed quotes. Add real entries and the sections appear on their own;
until then the page says the list is being confirmed.

The **interest form** is the same: `site.contact.interestForm.value` is `null`,
so `/contact/` shows an explanation instead of a form. Set it to a Google Form
or Cloudflare Function URL and the full form renders and posts there. Do not
re-add a form that collects names and emails and throws them away.

### Adding a photograph

Drop the file into `src/public/`:

- `src/public/team/nimisha-sivakumar.jpg` — matches the `photo` field in `team.js`
- `src/public/gallery/bootcamp.jpg` — matches the `file` field in `gallery.js`

The build checks which files actually exist. A person without a photo shows
their initials; a gallery tile without one shows a labelled placeholder and is
not clickable. Nothing is ever a broken image.

### Adding an event

Add an object to `events.js`. Upcoming vs. past is **derived from the date** at
build time — never write "Upcoming" by hand, or it will be wrong within weeks.

```js
{
  id: "founders-on-campus-nov",
  title: "Founders on Campus — …",
  date: "2026-11-14",        // ISO. endDate too, for multi-day events.
  time: "6:00 PM",
  venue: "Auditorium",
  audience: "Open to all",
  summary: "…",
  registration: "open",      // "open" | "closed" | null
  turnout: null,             // fill in afterwards
}
```

Rebuild and deploy regularly — the site's sense of what is next only updates
when it is rebuilt.

## How it is put together

```
build.mjs            the whole build: render pages, concat CSS, copy assets,
                     write sitemap.xml and robots.txt
src/
  data/              all content (above)
  pages/             one module per route; composes components with data
  templates/
    layout.js        <head>, header, footer — the document shell
    components.js    reusable pieces: button, chip, stat, event, person, tile…
    icons.js         inline SVG
    html.js          escaping, dates, the upcoming/past split
  styles/            concatenated, in order, into dist/assets/site.css
    tokens.css       colour, type scale, spacing, motion — the only file with
                     raw colour values in it
    base.css         reset and typographic primitives
    layout.css       containers, section rhythm, grids
    components.css   the reusable parts
    sections.css     page compositions
    motion.css       reveal animation and the reduced-motion rules
  scripts/app.js     progressive enhancement only
  public/            copied verbatim to the site root
tools/               og-card.html + make-og.mjs — regenerates og.png and the
                     touch icon with headless Chrome. Not part of the build;
                     the PNGs are committed.
```

### Design system in one paragraph

Taken from the official **E-Cell | PSGIM** brand sheet — *Ideas today. Impact
tomorrow.*

| | |
| --- | --- |
| Deep Navy | `#0D3B8E` — `--navy` |
| Royal Blue | `#0077FF` — `--accent` (interaction) |
| Ocean Blue | `#00B4FF` — `--ocean` (graphics only; 3.0:1, never text) |
| Light Blue | `#4FC3F7` — `--sky` |
| Pale Blue | `#E6F4FF` — `--accent-soft` |
| Typeface | Montserrat — Light 300 / Medium 500 / SemiBold 600 / Bold 700–800 |

An all-blue site slides very easily into generic-SaaS territory, so the blues
are held to the role of accent: a near-black navy (`--ink`) and cool paper
carry the page, and Royal Blue is spent on the things that should feel live —
the kicker rule, the active nav indicator, the emphasised word in the hero, a
reached stage on the arc. Hierarchy comes from weight and tracking within one
family rather than from mixing typefaces, which is also why the whole site
needs a single webfont. Corners are tight (3–10px) to echo the mark's straight
cuts.

**All colour lives in `tokens.css`.** If you find yourself typing a hex value
anywhere else, add a token instead.

### The mark

`brandMark()` in `src/templates/icons.js` draws the faceted **E** from flat,
solid facets rather than a traced gradient outline — at 34px in the masthead,
stacked translucent planes average into a single blue smudge and the letter
stops being readable. The same paths are duplicated in `src/public/favicon.svg`
and in `tools/og-card.html` / `tools/icon-card.html`; if you refine the
geometry, update all four and re-run `node tools/make-og.mjs`.

If you have the official vector artwork, that is better than this drawing:
replace the paths inside `brandMark()` with it and regenerate the assets.

### The arc

The homepage's signature section (`#arc`) is the four stages an idea moves
through at the Cell, threaded on one line that fills as you scroll. Each stage
lists the real programmes at that point, read from `initiatives.js` via each
initiative's `stage` field — so the showpiece cannot drift out of sync with
what the Cell actually runs. Add a programme, give it a stage, and it appears.

### /control/ — the team's QR generator

`/control/` holds internal tools. Right now that is a QR generator: paste a
link or any text, get a code with the E-Cell mark in the middle, download a
PNG at 512 / 1024 / 2048 px. `?q=<url-encoded>` prefills the box, so you can
send someone a ready-made link.

It runs entirely in the browser — the text is never uploaded. Encoding is the
vendored `src/public/vendor/qrcode-generator.js` (Kazuhiko Arase, MIT).

**Why the codes survive having a logo on them:** error correction is pinned to
level **H** (~30% of the code recoverable), the mark covers ~22% of the area,
and the 4-module quiet zone is preserved. Those three together leave real
margin for glare, wear and bad printing — but it is reliability, not a
guarantee, which is why the page says to test before printing.

**Two things that will bite you if you change this code:**

1. The encoder defaults to a one-byte-per-character function that silently
   mangles anything outside ASCII — an em dash becomes a control character and
   Tamil is destroyed. `qr.js` switches it to the bundled UTF-8 encoder on
   startup. Don't remove that.
2. Module size is floored to whole pixels, so the canvas is usually a little
   smaller than the size you picked (1024 → 984). That is deliberate:
   fractional modules land on different pixel boundaries and produce codes
   that scan badly.

The page is `noindex: true`, which keeps it out of `sitemap.xml`, adds a robots
meta tag and a `Disallow` line to `robots.txt`. That is **not** access control
— this is a static site with no accounts, so anyone with the URL can open it.
Don't put anything confidential there.

### Accessibility and motion

- One visible focus ring everywhere; nothing removes an outline without replacing it.
- The initiative rows expand on hover **and** on keyboard focus — a summary only a mouse can reach is one a keyboard user never gets.
- The lightbox is a `<dialog>`, so focus trapping and Escape come from the platform.
- Counters put the real number in the markup and restore it when the animation ends; the element is `aria-hidden` only while it is counting.
- `prefers-reduced-motion` forces revealed content visible *first*, then disables the decoration — so reduced motion can never leave content stuck invisible.
- Scroll effects only ever write `transform`, `opacity` or a custom property.

### Browser support

Modern evergreen browsers. `<dialog>`, `:focus-visible`, `color-mix()` and
CSS nesting-free plain selectors are all used; the lightbox checks for
`showModal` before binding and the gallery degrades to a plain grid without it.
